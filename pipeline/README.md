# Evidence Digest pipeline

Harvests newly-indexed PubMed studies across ~150 journals, classifies them
into reader-selectable topics with deterministic rules (no language model
anywhere), scores them, and emits a static JSON API + Atom feeds for GitHub
Pages. Python 3.11+, **standard library only** — no `pip install` step, ever.

## Install / run

Nothing to install. From the repo root:

```
python -m evidence_digest.cli <command>
```

or `cd pipeline && python -m evidence_digest.cli <command>`.

## Commands

| Command | Network | Purpose |
|---|---|---|
| `validate` | no | Validate the three config files. Exits non-zero on a bad config; this is what CI runs. |
| `check --days 120` | yes | Validate every journal `ta` against live PubMed. Flags zero-hit journals and any whose query didn't resolve to a `[Journal]` tag (a wrong abbreviation can still return free-text hits). |
| `harvest --days 3 [--max-per-journal 500] [--dry-run] [--only-journal TA]` | yes | Query every journal, drop already-seen PMIDs, fetch+classify+score the rest, write archive + seen store + run log. Prints per-specialty and per-journal counts, plus loud warnings for truncated or errored journals. |
| `build [--window-days N] [--site-url URL]` | no | Rebuild `data/api/` and `data/feeds/` from the committed archive. |
| `backfill --start YYYY-MM-DD --end YYYY-MM-DD [--dry-run]` | yes | Harvest a historical window one day at a time (uses absolute `mindate`/`maxdate`, since PubMed's `reldate` is always relative to today). |
| `stats` | no | Archive size, seen-PMID count, day coverage, last run. |

Set `PUBMED_EMAIL` (or `STUDIES_FETCH_EMAIL`) and optionally `NCBI_API_KEY` in
the environment — the key raises the E-utilities rate limit from 3 to 10
requests/second.

## Data layout

```
pipeline/config/journals.json        # journal registry (owned by editors, not this package)
pipeline/config/taxonomy/*.json      # one file per specialty (globbed, sorted by "order")
pipeline/config/scoring.json         # every tunable ranking/classification weight

data/archive/<YYYY-MM-DD>.jsonl.gz   # immutable per-day archive, keyed by entryDate, gzip mtime=0
data/state/seen/<YYYY-MM-DD>.txt     # PMIDs first emitted that day (dedup index, separate from archive)
data/state/runs.json                 # last 120 run records

data/api/manifest.json               # fetched first by the web app; everything else is discovered from here
data/api/taxonomy.json               # public slice of the taxonomy (rules stripped)
data/api/journals.json               # public journal registry (Sources page)
data/api/highlights.json             # top scorers, last 7 days, capped per specialty
data/api/search-index.json           # compact global index over high-score studies
data/api/topics/<slug>.json          # one file per topic, "lean card" shape (no abstract/sections/mesh/keywords)
data/api/days/<date>.json            # full study records for one entryDate (this is where abstracts live)
data/feeds/<slug>.xml, feeds/all.xml # Atom 1.0
```

`data/api/` and `data/feeds/` are build artifacts (gitignored, regenerated by
`build` every run). `data/archive/` and `data/state/` are the only things
that need to be committed — that is the entire point of the archive/seen-
store split: the repo stays small forever because nothing large is ever
rewritten.

## Module map

- `config.py` — loads/validates journals.json, taxonomy/*.json, scoring.json. Hand-rolled validation (no `jsonschema` dependency).
- `pubmed.py` — the only module that touches the network. Throttled E-utilities client with retry/backoff.
- `parse.py` — PubMed efetch XML → plain dict. Pure function, defensive against missing elements.
- `classify.py` — the rule engine: precompiled MeSH/phrase/acronym/veto matchers, one regex per topic.
- `score.py` — evidence-level detection + the 0–100 importance score.
- `takeaway.py` — extractive "why this matters" line. No model.
- `store.py` — archive/seen-store/run-log I/O.
- `build.py` — archive → static API tree.
- `feeds.py` — Atom 1.0 by hand with `xml.etree.ElementTree`.
- `cli.py` — wires everything together; the only place that knows how a parsed record becomes a `study.schema.json`-shaped record.

## How classification works

A topic is assigned when a study's accumulated match points reach
`scoring.json.classifier.assignThreshold`, summed from an independent MeSH
group and a phrase/acronym group (the single best-scoring field of that
group, never summed across fields — see `classify.py`'s module docstring).

**Short acronyms are capped.** Two-letter medical initialisms collide
constantly across specialties — AA (aplastic anemia / African American), ET
(essential thrombocythemia / embryo transfer), PV (polycythemia vera /
portal vein), MM (myeloma / melanoma), AI, RA, PE, DR, VF, OA, and more. A
bare "AA" in a title used to score the full `title` weight and, alone, clear
`assignThreshold` — filing an unrelated demographics paper into the
aplastic-anemia feed. `classify.py`'s `SHORT_ACRONYM_MAXLEN` (currently 2)
caps any acronym at or under that length to the `keywords` weight in every
field, including the title, so it can no longer assign a topic by itself; it
still combines with a genuine corroborating signal (a phrase or MeSH hit in
the same field, or a MeSH hit at all, since that's a separate rule group).
Do not "simplify" this cap away — it is load-bearing, not incidental.

## Adding a journal

Add an entry to `pipeline/config/journals.json` with the exact MEDLINE title
abbreviation (`ta`) — this is the only reliable journal identifier; full
titles and ISSNs both drift. Then run `validate` (offline) and `check --days
120` (network) — a zero-hit journal or a query translation missing
`[Journal]` almost always means a wrong `ta`.

Set `scope` to `all` for every article, `topic` for the top-level `topicFilter`,
or `virus` for the top-level `virusFilter`. The virus-focused option is for
broad microbiology journals; it retains virus–bacteria coinfection and
bacteriophage studies without globally excluding bacterial terms.

## Adding a topic

Add an entry to the relevant `pipeline/config/taxonomy/<specialty>.json`
file's `topics` array (or a whole new specialty file — the loader globs the
directory, so a new file needs no other change). Topic slugs are permanent
once shipped: they become URL paths, feed filenames, and stored subscriber
preferences, so rename by adding a new topic rather than editing an existing
slug. Every specialty needs exactly one `catchAll: true` topic to catch
studies that match nothing else.

## Tests

```
python -m unittest discover -s pipeline/tests -v
```

Runs fully offline against three committed PubMed XML fixtures
(`pipeline/tests/fixtures/`) and synthetic edge cases — no network calls in
any test.
